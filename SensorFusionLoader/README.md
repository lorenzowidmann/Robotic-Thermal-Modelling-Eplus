# SensorFusionLoader

Shared library, not a pipeline step. It is the single source of truth for the
rig geometry, imported by every module that has to put a LiDAR point onto a
camera image.

| file | what it does |
|---|---|
| `rig_calibration.yaml` | **the canonical calibration.** FLIR + ZED intrinsics and the LiDAR↔camera extrinsics, from an [LVT2Calib](https://github.com/Clothooo/lvt2calib) board-pose session (RMSE ~6 cm). Edit this, never the code, when a calibration is redone. |
| `rig_calibration.py` | loader for the YAML — returns the intrinsics/extrinsics as typed objects. |
| `projection.py` | generic LiDAR → camera pixel projection. Works for FLIR or ZED, given the matching `K`, `dist` and `T_lidar_to_cam`. Also provides `flir_fov_bbox_in_zed()`: which part of a ZED frame the FLIR can actually see, for cropping to the overlap. |

Points from `/cloud_registered` arrive already in the world/map frame (the SLAM
node applies the current LiDAR pose before publishing). To reach a camera's own
frame at that instant the projection undoes that pose, then applies the fixed
rig extrinsic, then the intrinsics:

```
world -> LiDAR-local (undo the pose) -> camera-local (T_lidar_to_cam) -> pixels (K + dist)
```

The calibration itself was produced with **LVT2Calib**
(https://github.com/Clothooo/lvt2calib) — automatic LiDAR↔camera extrinsics
from a board with four circular holes. The board templates it matches against
were generated by `../LVTCalibBoardGenearation/` with the real geometry of the
board that was built for this thesis.

## Used by

- `../EmissivityCalculation/project_to_flir.py` — material map from ZED onto FLIR pixels
- `../RadiometricCalibration/correct_session.py` — per-pixel distance for the atmospheric term
- `../PointCloudElaboration/WindowsDoorsDetection/` — opening masks onto the cloud

Nothing here is run directly; there is no CLI. Install into whichever venv is
importing it (see `requirements.txt`).

**FLIR frames must be rotated 180° before use** — the camera is mounted upside
down and the LiDAR↔FLIR extrinsic was derived on rotated images. The flag
`flir.rotated_180_before_calibration` in the YAML records this.
